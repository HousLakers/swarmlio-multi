## 改动 1：通信失效（心跳失联 → 队友接管）

**位置**：`failureCheckCallback`（0.5s 定时器，fsm.cpp）+ `reclaimGridsFromFailedDrone`（fast_exploration_manager.cpp）。


```cpp
// failureCheckCallback：心跳超时判定（drone_lost_timeout=3.0s）
double age = tn - states[i].last_heartbeat_;
if (age > fp_->drone_lost_timeout_) {
  states[i].is_lost_ = true;
  any_lost = true;
  expl_manager_->reclaimGridsFromFailedDrone(i + 1);
}
// 注意：心跳由 droneStateMsgCallback 刷新（25Hz 广播，收到即 last_heartbeat_=now、is_lost_=false）

// reclaimGridsFromFailedDrone：改为单一继承人
const double tie_margin = 0.5;  // health/reclaim_tie_margin (m)
int winner = -1;
double best = 1e18;
const auto& failed = ed_->swarm_state_[failed_drone_id - 1];
for (int j = 0; j < (int)ed_->swarm_state_.size(); ++j) {
  if (j + 1 == failed_drone_id) continue;
  const auto& s = ed_->swarm_state_[j];
  if (s.is_lost_ || s.health_status_ != 0) continue;  // 失效机不得继承
  const double d = (s.pos_ - failed.pos_).norm();
  if (d < best - tie_margin || (fabs(d - best) <= tie_margin && j + 1 < winner)) {
    best = d;
    winner = j + 1;
  }
}
if (winner != ep_->drone_id_) return;  // 非继承者：什么都不做
// ...继承者执行原吞并逻辑（self 插入 + failed 清空），随后 recent_attempt_time_=0 触发 ACVRP 重分配
```

**作用**：某机失联后 3.2 秒内，离它最近的存活机**唯一**认领其全部网格继续扫。

## 改动 2：定位失效（odom 断流/跳变 → 悬停 + 队友接管）

**位置**：`odometryCallback`（记录）+ `healthCheckCallback`（0.1s 判定），均在 fsm.cpp。

**原代码**：odom 回调只做位置/姿态存储，无健康判定。

**改为**：

```cpp
// odometryCallback 开头捕获相邻帧基线，尾部做断流/跳变记录：
const Eigen::Vector3d prev_pos = fd_->odom_pos_;  // 相邻帧对比基线
// ...原有 odom_pos_/odom_vel_/odom_yaw_ 更新...
ros::Time now = ros::Time::now();
if (fd_->have_odom_) {
  double dt = (now - fd_->last_odom_msg_time_).toSec();
  double dist = (fd_->odom_pos_ - prev_pos).norm();
  if (dt <= fp_->odom_jump_window_ && dt > 0 && dist > fp_->odom_jump_distance_) {
    fd_->last_odom_jump_time_ = now;                 // 0.1s 内位移>3m = 跳变
    ROS_WARN("[health] Drone %d odom jump: %.2f m in %.3f s", getId(), dist, dt);
  } else {
    fd_->last_good_odom_pos_ = fd_->odom_pos_;       // 悬停锚点
  }
}
fd_->last_odom_msg_time_ = now;

// healthCheckCallback 中的定位健康判定：
bool gap_ok = fd_->last_odom_msg_time_.toSec() > 0 &&
              (now - fd_->last_odom_msg_time_).toSec() <= fp_->odom_gap_timeout_;   // 断流>2s 失效
bool jump_ok = (now - fd_->last_odom_jump_time_).toSec() >= fp_->odom_recover_time_; // 跳变后静默 2s 才恢复
bool odom_healthy = gap_ok && jump_ok;
// 失效且处于飞行态（PLAN/PUB/EXEC）→ enterHealthHold(!gap_ok ? 1 : 2)
```

**作用**：odom 断流（>2s，reason=1）或位置跳变（0.1s 内 >3m，reason=2）→ 无人机立即悬停 + 广播 + 队友接管。断流由"最后消息时间"判定，跳变由"相邻帧位移超物理极限"判定（max_vel=1.5m/s 下正常 0.1s 位移约 0.15m，阈值裕量 20 倍）。

## 改动 3：建图失效（建图速率滑窗 → 悬停 + 队友接管）

```cpp
// sdf_map.cpp，新 public 方法：
int64_t SDFMap::consumeNewVoxelCount() {
  int64_t n = md_->new_voxel_accum_;
  md_->new_voxel_accum_ = 0;
  return n;
}
int SDFMap::countUnknownInSphere(const Eigen::Vector3d& center, const double radius,
    const int stride) {
  Eigen::Vector3i id;
  posToIndex(center, id);
  int r = (int)std::ceil(radius * mp_->resolution_inv_);   // 3.0m @0.1 → 30 体素
  int cnt = 0;
  for (int x = id(0) - r; x <= id(0) + r; x += stride)
    for (int y = id(1) - r; y <= id(1) + r; y += stride)
      for (int z = id(2) - r; z <= id(2) + r; z += stride) {

        if (!isInMap(q)) continue;
        if (md_->occupancy_buffer_[toAddress(q)] < mp_->clamp_min_log_ - 1e-3) ++cnt;  // UNKNOWN
      }
  return cnt;
}

// healthCheckCallback：10Hz 采样进 deque 滑窗（5s，n=0 也 push），失效判定：
if (in_active && !fd_->map_failed_) {
  bool unknown_ok = fd_->unknown_voxels_nearby_ >= fp_->unknown_min_count_;  // 周围未知≥30
  bool rate_low = fd_->map_rate_window_total_ < fp_->map_min_new_voxels_;   // 5s 窗新增<50
  if (window_valid && flying && unknown_ok && rate_low) {
    fd_->map_failed_ = true;
    enterHealthHold(3);
    fd_->map_rate_samples_.clear();          // 清空滑窗 = 恢复后 5s 再触发冷却
    fd_->map_rate_window_total_ = 0;
  }
}
// 恢复判定：最近 5s 新增≥30 或 周围未知<30 → map_failed_=false
// 注意：unknown_voxels_nearby_ 由 failureCheckCallback（0.5s）缓存，避免 10Hz 高频查询
```

**作用**：传感器/建图管线失效 → 约 8 秒判定 → 悬停 + 广播 + 队友接管。三重守卫（飞行中 + 周围有未知 + 速率低）防止已扫完区域/悬停/起步阶段误触发。

## 改动 6：公共机制（HEALTH_HOLD 状态 + 广播 + 自动恢复与重新融入）

**位置**：`EXPL_STATE` 枚举 + `enterHealthHold` / `recoverFromHealthHold` / `buildHoldBsplineMsg`（fsm.cpp）+ `DroneState.msg` + `optTimerCallback` / `optMsgCallback` / 接受条件三处豁免。

**原代码**：无悬停状态；DroneState 无健康字段；空闲机无法重新融入任务分配。

**改为**：

```cpp
// ① EXPL_STATE 新增 HEALTH_HOLD（EXEC_TRAJ 与 FINISH 之间），进入逻辑：
void FastExplorationFSM::enterHealthHold(int reason) {
  fd_->health_fail_reason_ = reason;
  fd_->static_state_ = true;
  fd_->hold_pos_ = fd_->last_good_odom_pos_;      // 锚定最后可信位置（非跳变后错误位置）
  fd_->hold_yaw_ = fd_->odom_yaw_;
  // 立即发布悬停 bspline（不发布则 traj_server 继续飞完旧轨迹）：
  bspline::Bspline hold = buildHoldBsplineMsg(fd_->hold_pos_, fd_->hold_yaw_);
  fd_->newest_traj_ = hold;
  bspline_pub_.publish(hold);
  swarm_traj_pub_.publish(hold);
  // 广播失效（保留网格供最近机认领）：
  auto& state = expl_manager_->ed_->swarm_state_[getId() - 1];
  state.health_status_ = reason;
  state.health_timestamp_ = now.toSec();
  state.recent_attempt_time_ = 0.0;
  transitState(HEALTH_HOLD, "healthCheck");
}
// buildHoldBsplineMsg：4 个相同控制点(order=3) + NonUniformBspline 取 clamped knots(8 项)
//   + yaw 4 点(yaw_dt=0.1) + traj_id=++local_data_.traj_id_（同 WAIT_TRIGGER 静态轨迹样板）；
//   hold 时长 5s，到期后 traj_server 自动保持终点零速 = 永久悬停兜底。
// FSMCallback 加 case HEALTH_HOLD（空转+节流日志）；safetyCallback active 判定排除 HOLD；
// swarmTrajTimerCallback HOLD 期间用 hold_pos_ 发静态轨迹（队友避让可见）。

// ② DroneState.msg 追加（广播/接收双向同步）：
int8 health_status        # 0=正常 1=odom断流 2=odom跳变 3=建图失效
float64 health_timestamp
float32 map_rate
// 接收侧另加本地守卫 health_reclaimed_（不广播）；收到 status==0 时清零。
// droneStateTimerCallback：HOLD 期间广播 hold_pos_ 而非断裂的 odom。

// ③ 自动恢复与重新融入：
void FastExplorationFSM::recoverFromHealthHold() {
  fd_->health_fail_reason_ = 0;
  fd_->map_failed_ = false;
  auto& state = expl_manager_->ed_->swarm_state_[getId() - 1];
  state.health_status_ = 0;
  state.health_timestamp_ = ros::Time::now().toSec();
  state.grid_ids_.clear();   // 网格已被继承者拿走，清空后经 pair_opt 重新领活
  transitState(PLAN_TRAJ, "healthRecover");
}
// 重新融入的三处最小豁免（仅放行空闲机，不全面改缺陷2/3）：
// a) optTimerCallback：urgent（自身网格空）时跳过候选机 attempt/interact 门槛
//    （激活原作者注释掉的 !urgent &&）：
//    if (!urgent && tn - states[i].recent_attempt_time_ < fp_->attempt_interval_) continue;
//    if (!urgent && tn - states[i].recent_interact_time_ < fp_->pair_opt_interval_) continue;
// b) optMsgCallback：自身网格空时总是接受派活：
//    if (!state2.grid_ids_.empty() && msg->stamp - state2.recent_attempt_time_ < fp_->attempt_interval_) { 拒绝 }
// c) 接受条件加救援条款：一方网格为空时跳过"总成本必须下降 0.1"检查：
//    const bool rescue = state1.grid_ids_.empty() || state2.grid_ids_.empty();
//    if (state_ != WAIT_TRIGGER && !rescue) { ROS_ERROR("Larger cost after reallocation"); return; }
```

**作用**：失效的公共响应（悬停 + 广播 + 接管 + 恢复）为五维共享；失效机自愈后经 pair_opt 领活重新起飞（实测日志链：`recovered, resume exploration → IDLE → Rescue reallocation accepted → optMsgCallback: from IDLE to PLAN_TRAJ`）。

## 改动 8：任务完成后的空闲机重新交换（IDLE → pair_opt → 重新起飞）

**位置**：`optTimerCallback` / `optMsgCallback` / `optResMsgCallback`（fsm.cpp）+ `allocateGrids` / `findUnallocated`（fast_exploration_manager.cpp）。

**原代码**：无人机扫完自己网格（巡游为空，NO_GRID）→ IDLE 后基本"退休"——空闲机选不中协商对象（候选机 attempt/interact 门槛），协商的接受条件仅"总成本下降 0.1"（给空闲机派活必然抬高总和，被拒绝），IDLE 的兜底是 100 秒才回出生点试一次。

**改为**（空闲机重新获得任务的三条路径 + 一套求解）：

```cpp
// ① 空闲机主动发起（optTimerCallback，0.05s 定时器）：
//    urgent = state1.grid_ids_.empty()（干完活的状态）；
//    urgent 时跳过候选机 attempt/interact 门槛（激活原作者注释掉的 !urgent &&）：
//    if (!urgent && tn - states[i].recent_attempt_time_ < fp_->attempt_interval_) continue;
//    if (!urgent && tn - states[i].recent_interact_time_ < fp_->pair_opt_interval_) continue;
//    → 空闲机能选中任何忙碌机发起协商

// ② 忙碌机发起时选中空闲机（接收方配合）：
//    optMsgCallback 中空闲机总是接受派活：
//    if (!state2.grid_ids_.empty() && msg->stamp - state2.recent_attempt_time_ < fp_->attempt_interval_) { 拒绝 }
//    → 忙碌机把活分给空闲机时不会被"频繁尝试"拒绝

// ③ 未分配网格拾取（findUnallocated）：
//    每一轮 pair_opt 都会把"无主网格"（missed）并入待分配集，随协商一并分出

// ④ 求解（allocateGrids）：两机网格并集 + 未分配网格
//    → LKH ACVRP（prob_type=2、MTSP_OBJECTIVE=MINMAX、容量=总未知×0.5×0.1）
//    → 得到两机最优划分 ego_ids / other_ids（空闲机按成本获得其份额）

// ⑤ 接受条件（optTimerCallback）：救援条款 + 原成本检查
const bool rescue = state1.grid_ids_.empty() || state2.grid_ids_.empty();
if (cur_app1 + cur_app2 > prev_app1 + prev_app2 + 0.1) {
  if (state_ != WAIT_TRIGGER && !rescue) {
    ROS_ERROR("Larger cost after reallocation");
    return;
  }
  ROS_WARN("Rescue reallocation accepted (idle side gets grids)");
}
// 救援条款的意义：空闲机进场必然抬高总路程（它得先飞过去），
// 若无此豁免，给空闲机派活的方案会全部被成本检查拒绝。

// ⑥ 确认后重新起飞（双方各自更新 grid_ids_）：
//    if (state_ == IDLE && !state2.grid_ids_.empty()) transitState(PLAN_TRAJ, "optMsgCallback");
//    ROS_WARN("Restart after opt!");
//    （optResMsgCallback 对称处理发起方）
```

**作用**：无人机干完自己的活后通过主动发起（①）或被动接受（②）的协商，经 ACVRP 从忙碌机处领到新的任务份额，立即"Restart after opt!"重新起飞。任务总量在全部存活机之间持续流动，直至全局完成（此时无前沿可派，IDLE 才是正确终态）。若忙碌机 0.1s 内刚尝试过协商，仍会拒绝空闲机的请求，0.5s 后自动重试

**相关参数**：`fsm/attempt_interval=0.1`、`fsm/pair_opt_interval=0.5`、`fsm/repeat_send_num=10`；
