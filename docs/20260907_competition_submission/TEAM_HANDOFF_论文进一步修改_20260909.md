本分支专门保存论文、图表、引用和审校材料。后续队友可以在这个分支上继续修改论文结构、文字、图表说明和引用；任何新结果都必须先经过证据登记，再进入正文。材料包不等于比赛指标已经完成，也不等于论文已经可以投稿。

## 2. 文件职责和唯一来源

### 2.1 正文、Word 和章节素材

`draft/paper_draft_v2.md` 是正文唯一主来源。修改文字、数字、章节标题、表格和图注时，先改 Markdown，再运行 `draft/build_paper_docx.py` 重新生成 `draft/paper_draft_v2.docx`。不要直接在 Word 中修改后再手工抄回 Markdown，否则会失去数字审计和图表可追溯性。

Word 稿是便于作者和队友阅读、批注和打印的派生文件。它已经嵌入 6 张 PNG 图；对应的 SVG、PDF、数据文件和 Archify HTML 在 [`figures/v2/`](figures/v2/) 中保留。Word 里用 PNG 是兼容性选择，不代表 SVG/PDF 被废弃。

`chapters/` 是按章节归档的素材和旧版证据说明，适合查背景和原始路径；它不是当前 v2 正文的自动组成部分。需要把章节材料吸收到正文时，先核对 `claim_ledger_v2.md` 和 `evidence_matrix.md`，不要直接复制旧段落。

## 3. 当前论文结构和写作边界

论文必须保持原 `论文框架.docx` 的七章顺序和小节名称。第一章使用 1.1—1.3；第五章统一为 5.1—5.3。当前顺序是：绪论 → 系统总体方案 → 关键技术 → 仿真实验结果 → 实机实验结果 → 应用创新 → 总结与展望。

正文不写日常调试、终端命令、SSH、参数试错、逐行日志或排障经过。具体文件路径、失败分类、hash 和纳入理由可以写进论断台账、QA 或交接说明，但不要把审计日志搬进论文正文。

正文中的缺失结果必须使用完整五字段格式：

```text
[待填-指标：单位；n=待补；场景=...；数据来源=...；run ID=待补]
```

不能填 `0`、`暂无`、`待补` 或自己估算的成功率来替代缺失数据。图表缺数据时保留空图位，不画伪造曲线、柱状图、轨迹或地图。

## 5. 数字和证据同步规则

新增或修正结果时使用以下顺序：

1. 确认精确来源：runroot、报告、metrics、manifest/approval 或实机记录；
2. 更新 `evidence_matrix.md` 的证据状态和来源；
3. 更新 `draft/claim_ledger_v2.md` 的论断、证据等级、run ID 和限制；
4. 重新生成 `draft/audit_v2/` 中的派生统计和图表数据；
5. 更新 Markdown 正文、表格和图注；
6. 运行 `build_paper_docx.py` 重新生成 Word；
7. 运行结构、数字、链接和引用检查；
8. 在提交说明中写明改变了哪些数字、哪些图和哪些证据状态。

数字不能只改正文。尤其要同步摘要、表8、图3、图3 CSV、数值台账和 Word。若无法找到精确来源，应保留旧值并标记待核对，不能凭报告截图或文件名猜值。

## 7. 推荐协作流程

### 文本修改

从 `draft/paper_draft_v2.md` 开始，在个人分支上修改。每次提交只处理一个主题，例如“重写 1.2 研究现状”或“统一图注和表注”。提交前运行 Word 生成脚本和静态检查，并在 commit message 或 PR 描述中列出数字是否变化。

### 新证据进入论文

新实验结果必须先有完整 run ID、执行台账、报告和 metrics。缺少其中关键文件时，只能登记为 `EVIDENCE_MISSING` 或 `INVALID_RUN`。不能把新结果直接粘贴进 Word，也不能修改原始 runroot 以适配正文。

### 图表修改

先修改生成脚本或数据接口，再重新生成 PNG/SVG/PDF；不要在图片软件里只改一张最终 PNG。若只调整排版，不得改变数据文件和图注中的 n、场景、来源或统计方法。

### Word 更新

```text
python3 docs/20260907_competition_submission/draft/build_paper_docx.py
```

生成后至少核对：Word 文件存在；`word/media/` 中有 6 张图片；表格数量仍为 15；章节标题仍为 7 章 20 节；正文中的缺失占位符没有被删除。不要直接在 Word 里修改正文作为唯一版本。

### 提交和合并

建议队友从 `paper-materials-20260909` 创建个人分支，例如 `paper-edit-related-work` 或 `paper-edit-figures`，通过 Pull Request 合并。不要直接向 `main` 推送。涉及数字、证据等级、正文结论或缺失状态的 PR，需要在描述中列出来源文件和验证结果。
