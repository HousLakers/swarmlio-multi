# 论文写作框架 v2（严格对应《论文框架.docx》）

状态：写作结构稿，不是最终提交版。正文只保留论文问题、方法、正式实验和结论；日常调试、终端命令、逐行日志、远端排障经过不进入正文，统一留在内部 `claim_ledger`/证据审计文件。

## 0. 总体定位

**暂定题目**：基于国产算力的多无人机具身智能实时感知、协同探索与弹性决策系统

**论文类型**：系统型、实验型工程论文。主线为：

> 国产边缘算力约束 → 激光惯性实时感知 → frontier 探索与任务分配 → 多机弹性决策 → 仿真/实机验证。

**写作口径**：所有章节按“完整实验叙事”的论文结构组织；已有结果填入真实数字，尚无结果的位置保留结构化占位符，不用调试细节替代结果，也不把占位符写成已验证成功。

## 2. 分节写作合同

### 第一章 绪论

#### 1.1 项目背景（简洁）

- 段落顺序：应用场景 → 技术矛盾 → 赛题指标 → 本文系统路线。
- 配图：图 1 系统总体流程图（传感器、LIO、地图、任务分配、规划、飞控）。
- 不写具体调试日期、终端命令、某次日志报错、未验证的“完全国产化”。

#### 1.2 研究现状（简洁）

- 四个综述模块：LIO/协同定位；frontier 探索；多机任务分配；通信丢包与故障弹性。
- 每个模块采用“已有路线 → 能解决的问题 → 局限 → 本文切入点”四句结构。
- 缺文献使用 `[CITATION_TODO: 主题/作者/年份]`，不写虚构引用。
- 配表：表 1 研究路线对比（方法、感知、协同、容错、平台、局限）。

#### 1.3 项目目标

- 用 3–5 个目标描述实时感知建图、frontier 探索、MINMAX 分配、掉线/丢包接管和边缘部署。
- 赛题指标映射表中无正式数据的单元写 `[待填-指标结果：测量方法/单位/目标值]`。
- 贡献声明避免“首次”“最优”“完全达成”等未经比较的绝对词。

## 4. 图表生产清单

1. 论文级总体流程图：Archify `dataflow`，复用 `topic_flow_dual_real.dataflow.json` 的语义，输出可嵌入 SVG/PNG。
2. 单机/多机感知—规划—执行图：简化节点，突出输入、状态估计、任务分配、轨迹和飞控反馈。
3. 任务分配统计图：从 `experiments/matrix_results.jsonl` 生成均值±标准差柱状图/散点图。
4. 容错统计图：coverage、Jaccard、overlap 和接管时间线；任务层丢包必须写图注。
5. 实机结果图：只绘制真实文件存在的轨迹、PGM、点云和统计；空字段不绘制伪数据。

每张图都必须有图号、结论式图题、数据来源、实验层级、场景、n、统计方法和限制说明。

## 5. 去 AI 化写作规则

- 先冻结数字、单位、指标名、引用键和结论，再做语言润色。
- 使用具体主语和动作动词，少用“值得注意的是”“综上所述”“本文旨在”“显著地”“深入探讨”“赋能”等模板化词。
- 每段只承担一个判断；首句给出段落作用，随后给证据，再给边界。
- 不堆叠“此外/同时/进一步/综上”；不使用空泛形容词和过度承诺。
- 保留技术术语和限定语；`polish-prose` 只能改表达，不能改数字、结果、引用和技术结论。
- 去 AI 化不是规避学校或比赛的 AI 使用披露要求；如规则要求披露，单独准备真实说明。

## 6. 生产顺序与迭代

```text
paper-profile（定位一次）
  → refactor-structure（确认七章结构）
  → literature-review / draft-related-work（研究现状）
  → 逐章框架确认
  → 生成 paper_draft_v1
  → verify-claims + verify-results + verify-citations
  → polish-prose（去 AI 化，不改技术内容）
  → reflect-paper / assess-paper
  → 绑定结果与引用后生成 v2
  → academic-pptx + build-slides/make-slides
```

每一阶段都保存版本和审计报告；只在用户确认后进入下一阶段。生命周期 skill 可以反复迭代，但每轮必须有明确目标、输入版本、外部校验信号和停止条件，不能无限润色或用重复生成掩盖缺证。
