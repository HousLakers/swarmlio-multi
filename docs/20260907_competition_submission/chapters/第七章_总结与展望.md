# 第七章 总结与展望：章节材料包

## 7.1 项目总结

### [可直接写] 已完成的阶段性工作

当前项目已完成或形成了以下可追溯阶段成果：

1. 建立了以 Mid-360/LIO、共享地图、frontier 探索、轨迹规划和 PX4 执行为主线的单机/多机系统框架。
2. 在 Gazebo/PX4 SITL 的 50×50 m、三机、GT registration 条件下完成了 A1/A2/A3、B1/B2/B3 和 C1 共 21 次矩阵运行，得到 MINMAX、容量参数和掉线条件下的可比较数据。
3. 实现并记录了单机掉线后的任务释放、最近邻接管和继续探索机制。
4. 实现并记录了任务层 20% 丢包注入、时间戳/幂等处理和自愈统计，报告级结果相对 0% 基线保持约 97.6% coverage。
5. 在 Khadas 节点上形成了单机实机点云/occupancy/PGM 基线，并完成了双机部署包、topic contract 和失败诊断材料。

### [可直接写但需限定] 当前数据能够支持的结论

可以得出：系统的感知—探索—规划—协同任务分配软件链已具备较完整的工程原型；MINMAX 在当前三机仿真代理场景下具有改善任务负载均衡的迹象；任务层掉线/丢包机制能够在阶段性仿真中保持任务继续推进；单机实机已能形成节点级地图产物。

### [必须如实写] 与赛题指标的对应关系

| 赛题要求 | 当前结论 |
|---|---|
| 室内 ATE ≤0.3 m | 有单机仿真 ATE 0.0802 m，但没有完整同口径室内正式 runroot，暂不能宣称指标闭环 |
| 室外峡谷/城市峡谷 ATE ≤0.5 m | 缺少对应实测/仿真 ATE，留空 |
| 三维地图 ≥5 cm | 有配置和 UAV2 单机 5 cm PGM，缺少双机融合验证，部分支持 |
| 单机 ≥10 Hz | 缺少统一正式频率统计，留空待补 |
| ≤20% 丢包任务连续 | 有任务层仿真报告，300 s 原始 runroot 尚未准确定位，需限定 |
| 多机协同定位/建图 | 有三机 GT 注册仿真矩阵，缺少真实 LIO 多机成功结果，需限定 |
| 在线重规划 ≤2 s | 无事件时间戳统计，留空 |
| 故障弹性 | 单机掉线仿真较明确，五维故障和实机故障闭环未完成，部分支持 |
| 总功耗 ≤30 W | 无测量材料，留空 |
| 全部国产化/自主可控 | 只有 Khadas 方向性部署材料，缺 SoC、OS、功耗和部件证明，部分支持 |

因此项目总结不能使用“完全对应赛题要求并全部达成”这一表述；更准确的总结是“完成核心算法原型和部分仿真/单机实机验证，关键多机实机和若干赛题指标仍待补证”。

## 7.2 项目展望

### [可直接写] 近期补证路线

1. 完成双机真实启动前的 frame、local_position、LIO—MAVROS 外部视觉话题、`drone_num/map_num` 和 `keys_topic` 统一检查。
2. 重新签发一次性实验 approval，给每架 UAV 保存启动命令、源代码 hash、参数快照、bag/ULog、local_position、LIO、轨迹、bridge 状态和视频编号。
3. 按室内三机、六机、十机和室外 AirSim 分别建立 manifest，避免用代理场景替代题目要求。
4. 增加 ATE（evo/真值）、LIO/地图频率、重规划事件延迟、机间安全距离、碰撞/急停和功耗仪表的统一采集。
5. 找回报告中 300 s 丢包 run32/run33 的原始 runroot；若无法找回，论文只引用报告级结果并说明可追溯性限制。

### [可直接写] 工程扩展方向

可继续完善通信、定位、建图、规划和执行五维健康管理，将 `HEALTH_HOLD`、任务回收、恢复和多机一致性纳入统一状态机；进一步把仿真中的 GT registration 替换为真实 LIO 注册，研究通信延迟、带宽和拓扑变化下的协同地图一致性；在 AirSim 中接通 RACER/ROS 多机接口后，再进行与 Gazebo 结果同口径的对照。

### [可直接写] 应用前景

若完成上述闭环，系统可面向室内未知空间搜索、灾害现场快速建图、地下/峡谷环境巡检、仓储和大型设施自主巡检等场景。多机协同的价值在于缩短覆盖时间并提高单机失效时的任务连续性；国产边缘平台的价值在于降低对外部高功耗计算节点和固定通信基础设施的依赖。

### [留空待补] 最终指标表和视频

当前没有最终外场实验、最终功耗表、国产部件证明表、实机多机指标表和演示视频文件。因此本节可以写计划和应用前景，但最终论文摘要、结论和比赛材料中的“指标达成”表必须等这些材料归档后再填。
