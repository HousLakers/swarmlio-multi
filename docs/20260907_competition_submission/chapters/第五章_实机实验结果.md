## 5.1 实验设置

### [可直接写] 实机系统和环境

实机验证以 Khadas 机载边缘节点、Livox Mid-360、IMU、PX4/MAVROS、ROS 和探索规划器组成。双机网络和启动路径由 `双机联合实机启动路径`、`deploy_real_fleet/`、`deploy_single_real/` 和 `deploy_uav2_real/` 管理；UAV1 与 UAV2 使用独立身份、话题和 `keys` 通道。动捕/VRPN 为实机位姿参考链路之一，LIO、外部视觉和 planner frame 之间通过 bridge 对接。

### [可直接写] 安全和启动顺序

实机流程按环境检查、传感器/飞控/位姿链路检查、LIO 与规划器启动、bridge/arm/OFFBOARD/hover 门控、记录和 teardown 分阶段执行。部署 README 明确 bridge 是具备 arm/OFFBOARD 能力的阶段，任何话题、坐标、心跳或资源门失败时应保持 fail-closed，人工接管优先。

### [留空待补] 实验条件表

当前文件夹没有一份能与某次正式实机飞行完全绑定的实验设置表，缺失项包括：场地尺寸和障碍布局、飞行高度/速度、光照/遮挡、动捕标定误差、LiDAR/IMU 时间同步误差、CPU/NPU/GPU 型号与负载、功耗采样方式、LIO/地图频率、飞行时长和视频编号。论文可以根据部署说明描述系统组成，但这些指标表需补原始记录后再定稿。

### 5.2.2 双机候选会话审计

较早候选记录位于：

- UAV1：`state/real_dual_audit_20260906/dual_last/board_192.168.43.151_id1/RUN-20260906T094101Z/`
- UAV2：`state/real_dual_audit_20260906/dual_last/board_192.168.43.59_id2/RUN-20260906T095719Z/`

审计确认两台 planner 都出现触发事件，触发时间差约 0.554 s；但该会话没有 arm/OFFBOARD/hover gate 的成功证据，也没有 local_position payload、bag 或 ULog。UAV1 约有 1.50849 m 规划轨迹、1080 个轨迹样本、coverage 字段 0.35607、cloud 3949、occupancy 5695；其 z 约 0.022–0.028 m，伴随 No path/Plan fail。UAV2 没有有效轨迹和 occupancy/map，coverage 字段来自少量旧样本，出现 Empty dominance/No grid。

因此该会话的结论是 `INVALID_RUN`，只能用于说明双机接口、坐标系和启动门控问题，不能用于证明双机起飞、双机协同定位、双机融合建图或无碰撞飞行。

### 5.2.3 目标 18:32 会话

用户指定的 2026-09-06 18:32 双机目标会话在当前工作区没有对应的 `RUN-20260906T1032Z` 或邻近 runroot、rosout、bridge、bag、ULog。UAV1 的 c89 记录在 18:30:46.380 左右结束，UAV2 没有更晚匹配证据。审计结论是 `EVIDENCE_MISSING`。

### 5.2.4 当前实机缺口

下列内容在本地没有形成可定稿证据：双机成功飞行、双机 ATE、双机融合 5 cm 地图、双机 LIO/建图频率、在线重规划响应 ≤2 s、20% 真实无线丢包、整机功耗 ≤30 W、第三架实机和最终演示视频。

## 5.3 实机实验结果总结

### [可直接写]

实机部分已经完成单节点感知/探索基线、双节点部署包、启动链路审计和失败诊断。单机结果表明至少一个节点可以生成点云/占据/PGM 等地图产物；双机审计则暴露了坐标系初始化、LIO—MAVROS 接口、ground node 语义、topic keys 和源码/二进制漂移等影响闭环飞行的关键工程问题。

### [必须如实保留]

当前实机证据不能支撑“多机实飞成功”或“已完全达到比赛指标”。建议将候选双机记录作为“失败案例与问题定位”小节，将完整单机记录作为节点级 baseline，并在展望中列出下一次实验必须同时保存的 manifest、启动命令、topic contract、local_position、LIO、规划轨迹、桥接状态、power log、bag/ULog 和视频编号。
