# 第二章 系统总体方案：章节材料包

## 2.1 系统总体架构

### [可直接写] 闭环架构

系统可按“感知输入—状态估计—地图管理—探索决策—轨迹规划—飞控执行—健康反馈”描述：

```text
Mid-360 点云 + IMU + 飞控/外部位姿
                 │
                 ▼
       Swarm-LIO / 状态估计与坐标变换
                 │
                 ▼
      局部占据栅格、点云地图、共享异步地图
                 │
                 ▼
           Frontier 提取与候选视点评分
                 │
                 ▼
      MINSUM/MINMAX 任务分配与 pair-opt 协调
                 │
                 ▼
        A* / kinodynamic / B-spline 轨迹规划
                 │
                 ▼
            traj_server → MAVROS/PX4
                 │
                 └── 状态、心跳、掉线和安全反馈回到决策层
```

仿真链路使用 Gazebo/PX4 SITL 和 GT registration 作为可控的多机协同基线；实机链路使用 Mid-360、LIO、ROS/MAVROS、PX4 和 Khadas 节点。论文必须把两条链路画成同一系统的不同验证配置，明确 GT registration 不是实机 LIO 误差验证。

### [可直接写] 多机通信和标识

实机双机部署采用共享 ROS master 和按无人机区分的 namespace、状态话题、规划话题及 `keys` 话题。当前审计确认管理地址 `.151` 对应规划 ID 1/UAV1，`.59` 对应规划 ID 2/UAV2。三机部署包为 UAV1/UAV2/UAV3 预留独立配置和 `keys_topic`，但第三架硬件地址仍为空，部署包明确标记 `execution_ready=false`。

### [可直接写] 安全闭环

系统把启动前资源/话题/参数检查、运行中 telemetry、轨迹安全、机间距离、掉线和 teardown 作为独立门控。仿真报告中的 `contact`、`abort`、telemetry completeness 等字段用于判断一次 run 是否可以进入论文；实机桥接层采用 fail-closed 的手动接管方式，未满足 arm/OFFBOARD/hover 条件时不应被描述为完成飞行实验。

## 2.3 软件与算法框架选择

### [可直接写] 软件分层

- 操作系统与机器人中间件：ROS 1/ROS Noetic 运行方式，配合 catkin 工作区、topic namespace 和 `/clock`。
- 仿真：Gazebo + PX4 SITL，Gazebo 作为唯一仿真时钟；2 UAV/3 UAV launch 文件为不同系统 ID、端口和 namespace 分配资源。
- 感知与定位：Swarm-LIO/LIO 节点接收 Mid-360 点云与 IMU，输出里程计、点云和地图相关话题。
- 规划与探索：RACER/ego-planner 风格探索管理器，执行 frontier 提取、候选点评分、路径搜索、轨迹优化和安全检查。
- 飞控接口：MAVROS/PX4，实机桥接器负责 arm、OFFBOARD、hover 条件和手动接管。
- AirSim：已经完成独立框架、构建/启动和只读 RPC 探针阶段；尚未与 RACER/ROS/PX4 形成论文所需的探索闭环。

### [可直接写] 关键配置

正式三机仿真配置 `config/3uav_static.yaml` 使用 `uav_count=3`、`map_mode=shared_async`、`registration_source=gt`、50 m × 50 m × 3 m 规划区域、0.05 m 体素配置、`MINMAX` 和 `capacity_factor=0.75`。launch 文件还允许切换 `MINSUM/MINMAX` 和 `0.75/0.5`，正式矩阵用 manifest 固定实验身份。

### [需限定] 版本和复现

工作区内同时存在当前源码、部署 overlay、远程快照、压缩包和历史备份。论文中算法版本必须以具体实验的 manifest、source hash 和 runroot 为准，不能把 `backup_khadas_ego/`、`state/pre_sync_*` 和当前 `SKM/` 混合成一份“最终源码”。详细运行证据应放在附录或复现实验说明，不必将全部日志写进正文。
